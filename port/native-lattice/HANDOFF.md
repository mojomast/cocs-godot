## Delivered workflow and APIs

`res://lattice/board.tscn` is a standalone native Control scene. Choose either locked map and cocs/cocs-coop, enter the endpoint, optionally specify an existing room, and connect. Normal create/configure/start calls use inherited PortNetwork. No command privileges are manufactured.

`godot/lattice/transport.gd` narrowly subclasses `res://net/client.gd`:
- `activate("hold", target_id) -> String`: empty string means queued locally, never proof of application.
- `activate("fighter") -> String`: PvP spawn Fighter, 12 FLUX; requires observed role allow-list, free thread and sufficient authorized FLUX.
- `action_gate(kind, target) -> String`: named reason or empty string. Base gate checks open connection, round/actor identity, health, one-second state freshness, sequence limit and cooldown.
- `changed`: UI refresh signal. `projection` contains only selected recipient fields, own local health/REQ and public nodes. No enemy actor-position layer or omniscient snapshot reads.
- `actions`: bounded 32-entry receipt history. Wire identity is roundRev/actionSeq; unique card IDs include round/peer/sequence. Reconciliation checks card ID, actor ID and peer ID, within the current validated round.
- Narrow `decode_text` handles bounded structured cocs-reject frames and delegates all ordinary traffic to the original decoder, preserving map validation and snapshot ordering.

Queued -> pending (server accepted) -> confirmed only on done/ok=true. Blocked/expired/refused is rejected with reason. Input ACKs never advance cards. Running HOLD is not reported as completed. A done card with reason replaced is shown with that reason and is not capture evidence.

Spend requires a fresh checkbox authorization each time, with duplicate activation suppression, no automatic spending retries, and no repeat until an outstanding spend settles. Explicit retry after rejection gets a new action sequence. Reset, results, identity change and disconnect clear presentation/pending state; round reset and disconnect also remove purchase authorization. Missing wallet fields are unknown/hidden, not zero. Explicit null node owner is neutral.

Co-op has separately read `command.slices`; ordinary authorized humans may issue HOLD. Economy is deliberately disabled, rather than applying PvP role-board rules to co-op's between-wave window/slice/executor economy. Both mode identities remain unchanged.

The UI is a native objective list, not the 3D world or a web clone. It shows labels, archetype, owner, live/contested status, coordinate tooltips, team resources and receipts. It does not require PortCatalog/world composition; the two explicit allowed identities match the locked contract. No shared integration patch was necessary.
