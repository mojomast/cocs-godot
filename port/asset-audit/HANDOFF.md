## Machine-readable deliverable and meaning

`inventory.json` is generated by `port/tools/asset_audit/inventory.py` using Python standard library only. Run from repository root:

```
python3 -B port/tools/asset_audit/inventory.py > port/asset-audit/inventory.json
python3 -B -m unittest discover -s port/tools/asset_audit -v
python3 -B port/tools/asset_audit/verify.py
```

The program itself writes only stdout/stderr and never executes JavaScript. Source file SHA-256 and size, PNG dimensions, PCM WAV metadata, ZIP member names (no extraction), exported function/class locations, manifest references, baked-bucket names, and optional Godot content presence are recorded. Every source/target path is repository-relative. No timestamps or host paths are embedded in generated inventory. Moth jobs retain only ID/engine/enabled/raw/bake, not authentication, job credentials, or full service metadata. Archive member names are metadata, not extracted repository paths.

Measured: 772 files, 438 manifest/file references, 95 Moth jobs. All inspected file references exist; all 36 announcer manifest SHA-256 values match. This is NOT a claim that every runtime reference resolves: computed keys, fallback routing, and JS imports are not a full static call graph. Categories below are manually traced separately. Inventory includes ordinary files, extensionless raw duplicates, and generated JS data; not just common media extensions. Broader repository scans found no tracked GLB/model interchange files. Generated Godot probe outputs are ignored and absent in this clean worktree.

Baked registry: 31 textures, 13 normals, 5 skies, 5 material LUTs, 10 effect sequences, 6 impulse responses, 1 audio bed, 4 motifs, 1 level graph, 1 seed record, 1 echo-space record, 95 provenance records. ## Formats, axes and conversion constraints

The original is largely Three.js procedural construction, not a directory of FBX/Blend models. `game/model-geometry.mjs` supplies beveled/contour/joined geometry, while operator/weapon code defines vertices and nested transforms. Animation is predominantly articulated rigid groups rather than imported skin clips. Inventory deliberately does not claim triangle totals, skeleton bone counts or final world-space bounds without evaluating those constructors.

Source `game/core.mjs:45-46` puts eye height on Y and yaw-zero aim down -Z; `MOVE` at line 174 records baseHeight 1.8, eyeStanding 1.45. These are authored units, not independent proof of meter calibration. Weapon chassis says +Z stock/-Z muzzle; pulse rifle muzzle Z is -.85 in `CHASSIS`. Viewmodel scale is 1.1 (`view.mjs:282`), and menu operator display scales to 2.15 (`:2572`): neither should silently become world-actor scale. Vehicle comments document +Z forward for siege/recon and some flying shapes. Validate each exported root with labeled axes, muzzle/feet anchors, winding and normal orientation; do not flip every mesh on Z globally. The Godot diagnostic currently maps actor x/y/z directly and adds .9 to center its capsule.

Moth bundled image planes are base64-decoded bytes (`moth-assets.mjs:16-38`); normals, color surfaces, roughness, emissive data and LUTs have distinct meanings. PNG dimensions and WAV metadata are inspected, not visually/audibly accepted. ZIPs include raw LUT/vocabulary results; extensionless raw duplicates are retained in inventory rather than presumed interchangeable. Current WAV set has 36 mono 24 kHz PCM16, 3 mono 22.05 kHz PCM16, and 6 stereo 22.05 kHz PCM16 files. Music bake documentation describes mono 44.1 kHz processing, normalization and loops; Ogg/AAC payloads were not decoded here.

Existing `tools/godot-export/harness.html exportObject` converts unsigned-byte RGBA DataTexture to canvas, expands InstancedMesh preserving transform/color, rejects BatchedMesh, removes userData, uses onlyVisible, and does not translate onBeforeCompile or runtime animation. Consequently it drops identity/rig metadata, excludes invisible variants, and cannot certify shader behavior. `exportMap` exports worldGroup, not the complete dynamic scene. Treat its probe as a useful starting point, not established all-assets parity. No exporter or runtime file was modified or run in this audit.

## Licensing and provenance review

No root LICENSE/COPYING/NOTICE file was found in this committed tree. `package.json` is private and does not supply an asset grant. Repository hosting/access and code authorship are not redistribution permission.

Music is the strongest documented chain: `assets/music/THIRD_PARTY_LICENSES.md` contains VSCO 2 CE / Versilian Studios and VCSL CC0-1.0 attribution plus upstream license snapshots; each of the 172 sample records declares CC0-1.0 and source URL. Preserve that notice and per-sample mapping in a future package. Raw music library sources are not in the repository. This audit checked repository declarations, not current upstream licenses or a bit-exact external source lineage.

Moth records identify engines, generation recipes and source inputs, but that is not an output license. Rights for input PNGs, seed WAV, vocabulary archives, provider outputs and output redistribution remain unknown. Do not infer permission from paid job metadata. OmniVoice announcer manifest identifies generator, seed, recipe and hashes but not model/output license or full rights chain. Verify those separately before shipping voices. Procedural SFX source calls its design original; that is a provenance claim, not a blanket code/asset license. Operator/weapon geometry is authored in repository code, but its redistribution grant remains unresolved with the missing root license. Names such as HALO_THEME in music code are not proof of copied recordings or proof of clearance; inspect composition provenance if releasing. No allegation or permission inference is made here.
