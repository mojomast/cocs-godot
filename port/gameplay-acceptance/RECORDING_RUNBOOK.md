Bounded recording runbook — planned session, NOT executed

Scope
record.mjs joins ONE existing approved room as an idle protocol participant. It does not create a room, start/restart rounds, host/configure a match, send input, or control any server. Its actor can be the controlled victim of a real human attacker. This is authority/protocol evidence for the recorder's actor, NOT native victim gameplay acceptance. A native victim requires primary-owned native instrumentation; this recorder cannot impersonate, share or reconnect to that native identity. Coordinate room capacity and permission for an additional participant before use.

Prerequisites and roles
Primary agent/operator owns the already running normal-rate server, explicit ws(s) endpoint and room ID, source revision/config evidence, approved existing map, start controls and cleanup of their own session. Human attacker uses ordinary supported controls and locates the recorder's mapped actor without debug damage, teleportation or altered rules. Recorder operator runs this standalone process only. Native observer owns separate Godot evidence and records actual victim identity, camera pose/look seed, pointer capture and attempted versus emitted input, correlated with server seq/time. Until that exists, these native observations are unobserved, regardless of protocol success.

Join before the primary operator starts the round, so the recording includes welcome, assignment lobby and start. A mid-round join may lack the required start witness and remain incomplete. Do not change timing: unlike tools/godot-fixtures/capture.mjs, this recorder never imports createGameServer or requests accelerated tickMs. Preserve current map and normal config; record their provenance separately. Obtain alive health>0/dead=0, then health=0/dead>0, then restored health>0/dead=0 for the same assigned actor in the same round, with death/spawn events where available. Round changes, replacement, missing state or disconnection cannot bridge a witness. Leave time for post-respawn snapshots within the fixed 120-second window. Do not restart to turn an incomplete recording into a pass.

Limits and cleanup
Connection/setup deadlines run from process start; setup means welcome received, not gameplay readiness. Overall deadline finishes an otherwise healthy bounded observation window; it does not imply a transition. Recorder exit 0 means completed window only. Exit 1 means interruption/disconnect/deadline-before-welcome/malformed/limit/error; argument/output errors also exit nonzero. Analyzer exits 0 established snapshot evidence, 1 incomplete, 2 invalid. Never conflate these meanings.
SIGINT/SIGTERM writes an unsuccessful completion marker and releases only this socket. On normal/error completion it requests close and permits 100 ms before process termination, bounding the native WebSocket closing handshake. Never stop shared game services or other clients. Operator releases human inputs and exits only their approved clients. SIGKILL/power loss cannot flush: absent or partial output is invalid, not acceptance. Existing output files are refused (exclusive owner-only creation). Temporary mock files are automatically removed, never promoted to genuine evidence.

Envelope cocs-recording-v1
frames retains existing client/direction/frame packet layout, but inserts direction=lifecycle records; legacy consumers MUST NOT read this envelope without an adapter. All records have client=1 and monotonic at_ms, ordered by array position. open is the WebSocket open event; close means observation ended/release requested, NOT confirmation of a completed transport close handshake. completion contains complete and reason; remote_disconnect is unsuccessful. round markers derive from changes in lobby/start.roundRevision; original packets remain the authority. No reconnect is attempted. Analyzer validates one open/close, timestamps, no packets outside the connection, final completion, and existing packet identity/round rules. Missing or unsuccessful completion downgrades even observed triples to incomplete. Witness locations remain in original frames indices. Legacy captures retain legacy limitations.

Known limits
Node 22 native WebSocket requires no installed npm package; canonical MESSAGE.JOIN and PROTOCOL_VERSION are imported read-only from game/protocol.mjs. Join/delta=0 follows server/game-server.mjs joinPeer and the existing fixture tool. This is not the full protocol validator. JSON parsing normalizes duplicate keys before storage; do not use against untrusted endpoints. Native WebSocket assembles each incoming message before the application limit check: max-bytes bounds retained raw-message bytes, NOT transport allocation or serialized envelope size. JSON envelope overhead adds bounded per-frame metadata. This is appropriate only for an approved trusted test server. No raw credentials are required; welcome.token/progressToken are redacted. Other payloads may contain participant data, so review before sharing. No native-client observations can be inferred from the idle protocol actor.
