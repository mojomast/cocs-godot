Authority: pickups
In game/core.mjs Match constructor (around 498), arena.pickups become {id,kind,x,z,y:floorAt(...),wait:0}. IDs originate from map array indices before mode filtering. Constructor filters pickups for mode loadout/mutators; never assume every authored marker survives. Match.step (1183–1187,1264–1265) advances wait=max(0,wait-dt), skips dead actors, moves living actors then automatically collects when !wait and 3D dist(actor,pickup)<1.05. E/interact is not collection. No separate client pickup command is involved. Match.collect itself checks usefulness, not distance/wait/death: direct unit calls do not prove the step/contact path.

Match.useful (1156) admits health below maxHealth, armor below 100, megahealth when HP below max or armor below 100. Ammo and weapon pickups require resolved pickupWeapon index, allowed loadout and ammo below that weapon's cap. Powerups and economy kinds always return useful. An instagib mutator rejects non-health/non-armor here, with additional constructor filtering. Match.collect (1157) heals 35 capped at maxHealth; adds armor 40 capped at 100. Megahealth is NOT a conventional uncapped overheal: health=max(current,min(maxHealth,150)), armor=min(150,current+75). Ordinary armor after megahealth is not useful above 100.

Ammo/weapon collection adds weapon magazine plus TOOL_USE.onPickup reload bonus, capped at weapon cap; unlimitedAmmo yields Infinity. If holding weapon 0 and not armsrace it selects collected weapon. POWERUPS table in game/data.mjs supplies duration/effect: collection resets the timer, refreshPowerups recalculates effects, shield effect sets temporaryShield and emits powerup. This differs from applyPowerup, which rejects already-active powers. Economy weaponUpgrade calls applyWeaponUpgrade (1162), selecting next allowed tier/wrapping and retaining original base while timed; deployable calls deploySentry (1165 onward). Since collect does not check those helper return values, consumption can occur without a successful economy effect: investigate before assuming each event guarantees effect. These variants are traced, not all covered by baseline acceptance scenarios.

Every successful collect sets wait=12 for health/armor, otherwise 15; increments stats.pickups; emits pickup {actor,kind,powerup,economy}. Event has no pickup ID/position. Correlate by snapshot ID/location and exclusive contact; two same-kind nearby supplies cannot be disambiguated from event alone. Return is wait reaching zero in active simulation, not wall time or an explicit reappearance event. Actor iteration means contested supplies need authoritative attribution. Ended matches freeze step timers; starting a fresh match creates fresh supply state. A player remaining in radius can immediately recollect if still useful, so leave the radius to observe return.

Authority: damage, death, respawn
Match.damage (836–873) exits for race, over, health<=0, protection>0, and depot apron immunity. Damage is not simply weapon.damage: one-shot/instagib, mutator/source multipliers, active resistance/brace/rider mitigation (maximum 0.5), COCS spotting, arrival protection and NPC facing shields apply. Class hooks run before sequential temporaryShield, juggernautShield, Alignment Review absorb and armor. Armor absorbs min(max(0,armor),remainingDamage*0.6); HP loses remainder and floors at zero. Damage event amount includes absorbed damage and actual HP loss; shield field covers temporaryShield only. shieldBreak uses temporary+juggernaut+armor totals and requires surviving HP. Friendly-fire exclusions also occur in individual fire/projectile paths; damage alone is not a universal team filter. Life steal uses actual HP loss. Do not derive exact lost HP solely from event amount.

Lethal damage sets health=0, deaths++, streak=0, dead=respawnDelay(), clears active/cooldown/movement/transient state, releases vehicle, drops flag, updates source frags (-1 self, +1 other), mode scoring and feed; emits death with actor, killer metadata, position and presentation descriptors. Frag limit can call endMatch on that same lethal step. Match.fall (885) is a separate path: lastValid fallback, fall/death events and void feed; it does not run ordinary damage/protection or the same frag-accounting branch. Do not test void rules by shooting. game/config.mjs and mode-specific systems change rules; baseline here is ordinary Meridian deathmatch, not a claim of parity for all modes.

Match.respawnDelay (1181) uses eliminationRespawn if finite, otherwise config.respawn. Normal config default 2 seconds, normalized 1–5 (game/config.mjs); RULES.protection=1.5 (game/data.mjs). Match.step decrements dead for health<=0 actors and calls spawn at <=0, then continues: automatic server action, not a respawn key. Match.spawn (798–835) mutates existing actor, retaining its ID, chooses supported location scored against enemies/exposure/projectiles/spawn heat/routes, applies pending loadout, resets HP to character/gear/NPC max, armor, loadout/ammo, dead=0, movement and powers, sets protection and emits spawn. Position need not equal original spawn. Protection prevents damage; do not assume immunity ends when player shoots without checking actual path.

Round over short-circuits Match.step and Match.damage. No timer-driven next round. Native session Enter sends start only from results phase, pending authority acknowledgement; started clears presentation. Team elimination, campaign/horde and COCS have separate objective/wave/regen rules requiring separate scoped acceptance work. Elimination lives are serialized, but a generic death timer is not proof that an eliminated team may continue playing. Do not alter modes or map selection for convenience.

Wire/client mapping
Match.snapshot (1310–1314) spreads actor state including id,health,maxHealth,armor,dead,protection,position,yaw,pitch,weapon,ammo,frags,deaths,powerups and shields, specialized movement/verb snapshots; nonfinite ammo becomes string '∞'. Pickups are copied with ID, kind, position, wait. Top-level time,over,overReason,config,feed,stats and objectives describe round state. server/room.mjs outboundState/quantizedCopy (around 758), per-peer filtering and snapshot/event dispatch form the authority boundary. godot/net/client.gd validates/decodes full snapshots and deduplicates events; native capture requests delta=0. Do not use this audit as permission to modify protocol or identities.

The client receives decisions/state, not collision/raycast reasoning, rejected usefulness attempts, spawn score candidates or exact intermediate modifier arithmetic. Many actor internals ARE serialized via spread: do not incorrectly classify all shields/verb state as server-private. Snapshot quantization/time sampling can obscure exact 12/15/1.5 starting values. Evidence should bracket transitions with server simulation time and permit a tick/snapshot interval, not an arbitrary latency claim. Welcome peer identity differs from lobby players[].actorId; ordinary spawn preserves actor ID, while roster reassignment and a new round are separate transitions. Use current mapping, not actors[0]. Missing actor means waiting, not death.

Acceptance procedure
Detailed prerequisites/actions/authority/native/capture/pass/fail/investigation fields are in catalog.json. Use Meridian authored health (-6,22) and rocket (-14,-19), floor y from authority. Positions are grounded in game/destination-combat-maps.mjs plan; exact walkable approach from random spawn remains a live investigation. Native session supports mouse look/left fire, WASD, Space, R, Shift, Ctrl, E, F, Esc and results Enter (godot/world/session.gd). No pickup key, respawn key or assumed weapon switching key. Session currently creates its own room; a reproducible human attacker/victim setup needs primary-agent-owned join support or an approved existing harness. Do not quietly use debugger teleports/HP edits or fabricated state as live acceptance.

Record actual config and current actor mapping first; bracket state transitions and event IDs in a small capture, plus visible HUD/marker evidence. A human can navigate existing corridors, take nonlethal fire, collect, leave radius, and then undergo lethal fire before round end. Treat failed setup (blocked route, competing bot, missed snapshot, expired round) as inconclusive with reason, not pass. Numeric comparisons must account for armor/shields/modifiers and simulation sampling. Visual/audio parity is outside this audit; diagnostic behavior is the expected current baseline, not asset acceptance.

Suspected defects / hypotheses, not reproduced failures
1. PortLocalLifecycle and presentation classify alive from dead<=0 without consulting health. Investigate zero-health/zero-dead retained actors, particularly mode-specific actors. Normal Match.step immediately spawns at timer expiry, so no baseline wire failure is established.
2. Economy pickup useful=true plus unchecked helper return may consume a pickup with no deploy/upgrade effect. Verify intended rule before calling it a defect; do not change gameplay to make tests easier.
3. No pickup-specific feedback exists in native combat feedback, only marker/HUD changes. This is an observed diagnostic limitation, not proof of missing authority collection.
4. Insufficient recorded snapshot continuity is an evidence gap, not a gameplay bug.
