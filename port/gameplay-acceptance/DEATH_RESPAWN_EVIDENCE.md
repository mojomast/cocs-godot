Death/respawn evidence analyzer contract

Scope
Offline inspection only, at audit base 1206e41cce014c2413ef1670325d20f56c9324be. The analyzer reads an explicit JSON path and never writes it. No dependencies outside Python's standard library. This is not the protocol validator or a gameplay implementation. It evaluates locally assigned actors, independently per capture client connection, not arbitrary bots. Minimal synthetic fixtures are relevant-field projections, not complete protocol conformance fixtures.

Source basis
 tools/godot-fixtures/capture.mjs connect(): records {direction, client, frame} in callback/array order. client is socket creation index, not peerId or actorId. There is no capture wall timestamp, close record or terminal-completion marker. The generator retains only early snapshots and explicitly appends the ACK snapshot again; event traffic is retained. report.snapshot_count is not retained sample count. Report is metadata, not frames.
 server/room.mjs lobby() serializes full roster, connected/spectate, actorId, roundRevision. startMatch() broadcasts lobby before start, increments roundRevision and creates the Match. Reconnect sends welcome/start; welcome is therefore a hard connection boundary even with the same peer and actor. Snapshot seq is room-owned, increasing across rounds, not a simulation timestamp; per-client gaps are legal. Results do not carry snapshot seq.
 game/core.mjs Match.emit() assigns serial id and simulation time, retaining at most 300 events. room dispatchEvents() advances per-peer lastSerial and filters events. Missing serial values are not by themselves invalid. No assumption of event completeness or adjacency is justified.
 Match.damage()/fall() assign zero health and positive dead timer and emit death; Match.step() decrements timer and Match.spawn() restores health/dead on the same object/ID, emitting spawn. Snapshot copies health/dead/id; snapshot.time and event.time use simulation seconds. Round end stops simulation. A spawn can also initialize an actor, so spawn alone does not prove respawn.
 godot/net/client.gd decode_text(): lobby replaces local assignment; start resets round; stale snapshot seq is ignored; events deduplicate by id; results close round. Actual delta spelling is snapshot-delta. Closed WebSocket clears mapping in _process(), but that transport observation is NOT recorded by the existing capture format.
 godot/world/local_lifecycle.gd apply(): dead>0 drives native dead status and alive-after-nonalive sets reseed_look. This source behavior is not recorded camera or control execution evidence. This analyzer deliberately requires health as well as dead, unlike that presentation classification.

Strict criterion
Require welcome identity, authoritative start roundRevision and matching lobby mapping (lobby may precede start). Within one uninterrupted mapping/round/connection segment require three time-increasing full snapshots with over=false: health>0/dead=0; health=0/dead>0; health>0/dead=0. Repeated snapshots in a phase are permitted. ID is matched explicitly, never actors[0]. Positive HP with positive timer or zero HP with zero timer is ambiguous and breaks continuity. Disappearance breaks continuity and proves neither death nor reassignment.

Established means at least one observed snapshot witness, not an assertion that every intervening simulation tick was captured. snapshot_observed distinguishes this from event_corroborated, which additionally requires the same actor's death event in (alive_before.time,dead.time] and spawn in (dead.time,alive_after.time]. Event ID/time and locations are checked, with no rounding tolerance invented; quantized coincident boundaries may therefore conservatively lose corroboration. Event corroboration does not certify complete event delivery, one and only one intervening death, camera reseeding, dead-input gating, human intent, native rendering or normal-rate execution. Synthetic established results remain synthetic.

Incomplete means structurally usable evidence lacks a qualifying triple (including sparse/event-only evidence, missing identity or missing start). Invalid means unusable relevant schema/order, unsupported deltas/transport markers, bad JSON, duplicate object keys, nonfinite values or file-read failure. Any invalid record invalidates the entire result, including a previously found witness. JSON parse truncation is invalid; syntactically complete shortened captures are indistinguishable from intentional prefixes and can only be judged by retained observations. A valid prefix containing a triple establishes that triple, not successful session completion.

Ordering and boundaries
Never sort records to manufacture continuity. Array order is receive order per client. New snapshot seq must increase and simulation time cannot decrease within a round. Exact previously seen snapshots/events are ignored; conflicting duplicates and unseen backward seq/event id/time are invalid. This is stricter than the native decoder's silent stale-frame dropping, to avoid concealing recorder corruption. Full snapshot sequence numbers need not be contiguous. Event ordering is independent of snapshot ordering; compare simulation times for corroboration, not packet adjacency. Client input seq is not snapshot seq or a death clock.

Welcome, start (even repeated start), round change, results/over, decoder error, roster revocation/disconnection/reassignment, missing actor and ambiguous health all prevent stitching. A complete earlier witness survives later ordinary boundaries, but not malformed data. Capture client indices must uniquely identify actual sockets. Reuse without welcome, omitted reconnect/start/lobby messages or forged metadata cannot be detected universally. Unknown normal message types are ignored, not interpreted as state. Explicit undocumented disconnect/close/revoked markers are rejected rather than guessed. Transport-disconnect support for another recorder needs a separately documented adapter; the existing recorder lacks transport-close records. These trust limitations must accompany any claim.

Interface
python3 -B port/tools/gameplay_acceptance/death_respawn.py PATH
python3 -B port/tools/gameplay_acceptance/death_respawn.py PATH --json
Exit 0 established, 1 incomplete, 2 invalid (including argument errors). JSON uses sorted keys, no wall time/path-dependent values, zero-based $.frames[N] locations and stable encounter order. Human output names witnesses and always states camera/control unobserved. Input provenance labels are echoed, not authenticated. Counts are per receiving client, not unique global events. dead_snapshots counts mapped local actors only; snapshots counts full packets after exact duplicate suppression. Results are boundaries, not intermediate dead-state samples.

Synthetic regression fixtures
fixture() in test_death_respawn.py is explicitly synthetic. Tests mutate it for event-only/sparse death, absent actors, changed IDs, revoked mapping, disconnected roster, fresh welcome, round restart, results, split connections, absent identity/start/mapping, zero-health/zero-dead ambiguity, wrong event actor/time, snapshot-only witnesses, duplicate/conflicting/out-of-order data, unsupported transport/deltas, malformed/truncated JSON and missing files. CLI subprocess tests check real 0/1/2 exits, deterministic JSON, human output and byte-identical input after analysis. These passes test the analyzer, not gameplay acceptance.
