# Native atmosphere graphics lane

Branch `graphics/atmosphere`, baseline `b0ac0b5`. Owned runtime code is exclusively
`godot/graphics_atmosphere/`; tests are in `godot/tests/graphics_atmosphere/`.
The shared viewer, surface style, session, source maps, source Moth textures and
export tooling are unmodified. The capture harness stages its own project.

## Integration contract

```gdscript
const Atmosphere = preload("res://graphics_atmosphere/atmosphere.gd")
var atmosphere := Atmosphere.new() # one instance per viewer, reused across maps

# In load_map, after style.configure and before rendering:
atmosphere.configure(map, environment, sun, sky_texture)
# After style.decorate(map, world):
atmosphere.decorate(world)
```

- `configure(map: Dictionary, environment: WorldEnvironment,
  sun: DirectionalLight3D, sky_texture: Texture2D = null) -> void` installs the
  controller-owned environment and configures the existing directional light.
- `Atmosphere.sky_name(map: Dictionary) -> String` returns one of `nebula`,
  `ashen`, `frost`, `void`, `ember`. Pass the concurrent library's
  `library.sky(Atmosphere.sky_name(map))` as the fourth argument. Expected files
  are `res://moth/generated/sky/{name}.png`. There is no loader preload or
  dependency in this lane; null is a fully working gradient-sky fallback.
- `Atmosphere.profile(map: Dictionary) -> Dictionary` returns a deep copy of
  finite, authored art settings. All nine source IDs are explicitly selected.
  Unknown metadata gets the Meridian palette; no map is added to the catalog.
- `decorate(world: Node3D) -> void` is idempotent and allocates no nodes. It
  changes only `NativeWorldDetail/DistantGround`'s material and hides the
  baseline `SkylineDetails` / `RidgeDetails` MultiMeshes. These are synthetic
  scenery generated by `environment_style.gd`, outside playable bounds.
- `clear(environment: WorldEnvironment) -> void` releases the retained panorama
  and detaches the environment only if this controller still owns the slot.
  Call on teardown if the controller outlives the viewer; otherwise dropping
  the controller and viewer references releases everything normally.

[`integration.patch`](integration.patch) is an **unapplied**, baseline-compatible
four-hook patch using the null-texture fallback. The lead can apply it with
`git apply port/native-atmosphere/integration.patch`, then pass the Moth library
texture in the configure call once the asset lane is integrated. The existing
surface-style configure must run first because it assigns the environment.
The inherited session receives this through the viewer; no session edit needed.

## Map identity and source-sky rationale

Source phase, tags and identity were inspected in `game/destination-*-maps.mjs`
and the read-only generated catalog. These are native art choices, not exact
reconstructions of the WebGL scene.

| Source ID | Source identity / phase | Baked sky | Maximum mix | Native direction |
| --- | --- | --- | ---: | --- |
| meridian-exchange | Urban civic transit / dusk | nebula | 22% | Slate-violet zenith, warm rose limestone haze, warm side key, cool shadow fill. Cosmic detail is secondary to the city. |
| verdant-reliquary | Living ruins / day | frost | 0% | Muted cyan daylight, soft green-white horizon and high cloud veil. Space stars would contradict the forest daylight. |
| ember-crucible | Volcanic furnace / night | ember | 66% | Burgundy night, elevated orange nebula, ash horizon. Neutral-cool fill distinguishes ramps and iron from warm accents. |
| tidal-citadel | Snowbound naval forts / day | frost | 10% | Icy blue zenith and pale maritime haze. Low panorama strength preserves cold daylight and snow contrast. |
| sunscar-convoy | Canyon freight / dusk | ashen | 10% | Copper dust horizon and desaturated mauve upper sky; small ashen contribution supplies texture without turning desert dusk into space. |
| asterion-relay | Orbital observatory / night | void | 82% | Deep indigo upper sky, blue airglow horizon and readable cool relay masonry. Explicit ID wins over source `biome: ruins`. |
| monsoon-foundry | Forest dam / day | ashen | 0% | Green-gray overcast veil, broad ambient fill and restrained key; no star field under daytime rain clouds. |
| ion-speedway | Orbital road course / night | void | 68% | Blue-black sky and cyan horizon. Stronger stable fill preserves asphalt, rails and gate silhouettes at speed. |
| aurora-stadium | Floodlit sports pitch / night | nebula | 48% | Teal-blue night with a restrained nebula; high cool fill preserves pitch markings and player/ball contrast. |

The panorama fades from zero at elevation `EYEDIR.y = 0.08` (~4.6°) to the
listed strength at `0.46` (~27.4°). The baked equatorial band is lifted into the
upper sky. Upper/lower gradients meet with zero slope at the mathematical
horizon. A wrap crossfade handles potentially non-tiling source panorama edges.
Static veils and the sun disk are shader colors, not particles or extra lights.

## Readability, resource ownership and cost

- Linear tonemapping with fixed exposure, ambient energy 0.66–0.80 and key
  energy 0.62–0.82. No exposure adaptation or performance adaptation.
- Fog density 0.00030–0.00090: the exponential model retains at least 91.4% of
  scene radiance at 100 m, and at least 80.6% at 240 m. Fog does not affect sky;
  the sky/ground shaders supply the distant haze independently.
- One reused `Environment`, `Sky` (128 radiance), sky material and ground
  material per viewer. No per-frame scripts, particles, additional geometry,
  extra lights, texture generation, or cross-map texture cache. The material
  holds only the most recently supplied external texture.
- Sky uses two filtered panorama samples when enabled plus smooth gradients,
  one sine and fixed-power halo; daytime profiles skip panorama sampling.
  The distant-ground shader replaces the existing plane material. Hiding the
  old scenic ring removes its visible draw rather than adding a second skyline.
- Existing 220 m, four-split directional shadows retained. Glow, SSAO, SSIL,
  SSR and volumetric fog explicitly disabled. Actual captures use Compatibility
  OpenGL under llvmpipe; there is no hardware frame-time claim.

### Bounded shared-scene defect found

The baseline's dark 1800 m plane has a visible outer edge. Its 28 synthetic
city boxes / five-sided ridges also read as a chunky ring against the horizon,
including on the orbital maps. A sky shader alone cannot remove these opaque
silhouettes. The `decorate` hook is the bounded fix: keep the lowered plane's
exact mesh/transform, color-fade it into the horizon with camera-relative
distance, and hide just those two generated scenic MultiMeshes. This preserves
all source solids, coordinates, supports, collision, trim, trees and landmarks.

## Reproduce verification and captures

```sh
python3 port/native-atmosphere/run.py
# Or headless checks only:
python3 port/native-atmosphere/run.py --checks-only --output /tmp/opencode/atmosphere-checks
```

Requires the pinned Godot 4.5.2 executable, Python 3 and Xvfb. `--content` can
point at an existing generated semantic catalog (default: primary read-only
catalog). The helper copies the project and catalog into an owned temporary
staging directory, copies only the five existing Moth sky PNGs (bounded at
4 MiB each), records SHA-256 provenance, and deletes staging on exit. It never
writes `godot/moth`, shared generated content or export tools. Xvfb uses
`-nolisten tcp -nolisten unix`, isolated XDG directories, bounded subprocesses
and owned-process cleanup. `PORT=0`; no HTTP service is required.

Tests exercise all nine explicit profiles, recursively read-only source maps,
finite light/sky settings, malformed bounds, fallback selection, 108 texture
replacement/map switches, stable resource identities, prior texture weakrefs,
controller release, idempotent scenic hooks, and safe environment ownership.
The graphical harness also samples actual rendered pixels above and below the
sky horizon for each map and records narrow horizon strips. It captures all nine maps and paired overview/street-height
views for Meridian, Ember and Asterion at both 960×640 and 1280×800. It records
exact cameras and settings in per-phase manifests. These are offline art
captures of the native world, not live objective/weapon acceptance.

### Confirmed shared terrain-color defect and bounded recommendation

The shared viewer converts terrain vertex colors on the CPU with
`style.terrain_color(triangle).srgb_to_linear()`. In this Compatibility pipeline,
those vertices render substantially darker than the same palette supplied as
material colors. This affects floors and roof/support triangles independently
of sky quality. Global ambient increases alone would over-light walls while
leaving Ember's dark ash terrain poorly legible.

A private staging-only probe removed that single conversion, keeping the same
Ember camera, lights, atmosphere, source dictionary, shader and all coordinates.
Both the [street result](evidence/terrain-color-probe/1280x800/after/ember-crucible-street.png)
and [overview result](evidence/terrain-color-probe/1280x800/after/ember-crucible-overview.png)
are retained. The street result was opened directly: ash floor panels, the
foreground shadow boundary, roof underside and ramp are clearly readable,
while wall and sky appearance remain identical.

[`terrain-color-integration.patch`](terrain-color-integration.patch) is the
unapplied one-line **Compatibility-targeted** recommendation for the lead's
shared viewer integration. Coordinate/collision data are unaffected. Since it
changes all semantic terrain colors, the lead should review the integrated
all-nine material lane, particularly snow and sand. A future linear-renderer
port should handle vertex color conversion in the appropriate shader path.

## Limitations

The finite scenic plane is designed for authored playable camera positions,
not arbitrary flights beyond its 1800 m extent. The old skyline ring is hidden,
so aerial views expose the semantic map's rectangular footprint more plainly;
new biome-specific distant geometry would be a separate art pass. Source skies
are low-resolution baked PNGs, and enlarged stars look soft in first person.
Sky colors are static. Camera-matched captures verify the native environment
and architecture; live objectives, weapon silhouettes and final Moth material
composition still require the lead's integrated review. Source terrain's color
conversion and baseline close-up surface/shadow moiré are outside this lane's
runtime ownership; the verified terrain recommendation is supplied above.
