# Multiplayer Worlds — non-urban authored set

Five distinct map templates live in `tools/godot-multiplayer/worlds/recipes.mjs`.
`node tools/godot-multiplayer/worlds/build.mjs` writes deterministic, identical
JSON to `port/native-multiplayer-worlds/worlds/` and
`godot/multiplayer_worlds/generated/worlds/`, with a SHA-256 manifest. These
are port-owned new maps, not aliases of source maps. Host and guest must load
the same recipe and the same visual GLB, keyed by exact map ID.

| ID | Geometry / traversal | Proposed experience → modes |
| --- | --- | --- |
| `breakwater-exchange` | Dockside freight switchback, two drydock/shipyard flanks, through-sheds, cranes, four vehicle bays | zones → domination; assault → assault; objectives → payload; combined-arms → combined-arms; combat → deathmatch/teamdeathmatch |
| `thermal-divide` | Geothermal alpine stations, three contrasting crossings, a grounded 4 m raised bridge and through-halls | objectives → ctf; zones → domination/koth/uplink/holdout; assault → assault; combat → deathmatch/teamdeathmatch/instagib/rockets; arms-race → armsrace |
| `sirocco-circuit` | Purpose-built desert Puma loop with 14 directional checkpoint gates, offset turns, canyon overpass and eight-car grid | sports → puma-race |
| `copper-bowl` | Purpose-built symmetric copper stadium, bounded flat pitch, 16 m goal mouths and 5 m net pockets | sports → puma-soccer |
| `tern-archipelago` | Seven-node strategic archipelago, five capturable sectors, three physical causeway identities, two HQ depots + two neutral forward depots | lattice and lattice-world → cocs/cocs-coop |

## Shared integration contract (owner: urban/integration lane)

1. Extend the reviewed package, launcher, menu, scene mode-map allowlists and
   source-compatible authority/catalog registration with only the pairs above.
   Source locked maps remain untouched. `modeBindings` is declarative routing,
   **not** an automatic permission to join an unmatched source authority.
2. Import each `*.json` map template into the shared catalog adapter with its
   source-consumed fields intact: `blocks` are ground-up solids; `terrain` is
   authoritative support; `race`, `nodes`, `lattice`, `lanes`, `terminals`,
   `depots`, `vehicles`, `objectiveZones`, `flagSpawns`, `teamSpawns` and
   `navNodes` are used by their existing source modes. Bind the same JSON on
   host and guest and reject hash mismatches before joining.
3. Provide collision for the `overhead` arrays (world-space AABBs with
   `minY/maxY`) for roof slabs and the gantry/overpass. Existing ground-up
   `blocks` cannot model walk-under roofs without sealing ground doors. No roof
   walkability is advertised. The exporter builds matching elevated meshes;
   until the common runtime implements overhead collision, **do not expose**
   these maps as fully verified.
4. `breakwater-exchange.payloadPath` is an authored wayline. The current source
   payload picks its endpoints from first team spawns; consuming this wayline
   in the common payload adapter is needed for the freight switchback rather
   than a straight-line cart through the lock house. Its first/last points are
   the actual first team spawn positions.
5. For `thermal-divide`, preserve *both* complete ground support and elevated
   bridge terrain triangles. The bridge top ramps from 0 to 4 m across 16 m;
   preserve its Y heights for grounded nav and ray collision.
6. Sports: pass `race.gates` in authored order and its 8-slot `grid` to the
   source Puma race; `copper-bowl` uses `race.kind='soccer'`, `pitch`, `goals`,
   `ball`, and a separate 4-slot Puma grid. Route target limits must use mode,
   not an old map-ID test (`ion-speedway` is currently hard-coded for race).
7. Lattice: retain authored node IDs and graph edges; don't infer a new topology
   from physical bridges. Renderer should use JSON `art` / exported GLB while
   authority owns the exact `blocks`/`terrain` geometry and objective sockets.

The following hard-coded scene gates currently also require integration:
`godot/sports/demo.gd` (two map IDs), `godot/lattice/world_demo.gd`
(`WORLD_MAPS`), and package `options.mjs`. The native catalog's static entry
and the authority map allowlist are separate checks; both must admit a new ID.

## Source, export and visual budgets

Editable Blender masters and optimized GLBs are generated by
`tools/godot-multiplayer/worlds/blender_export.py`. This is a **heavy** step:

```
node tools/godot-multiplayer/worlds/build.mjs
LP_NUM_THREADS=1 /home/mojo/.tmp-on-disk/cocs-blender-toolchain/blender-4.5.14-linux-x64/blender -b -t 1 --python tools/godot-multiplayer/worlds/blender_export.py -- breakwater-exchange
```

Repeat the Blender command for each map ID. The `.blend` stores individually
named editable parts; GLB batches geometry into one mesh per material (typically
<16 material draw batches). Re-export never reads or mutates source assets.
Each JSON has an independent, human-readable geometry and marker contract; no
GLB triangles are promoted to broad approximate authority colliders.

Cheap checks: `node --test tools/godot-multiplayer/worlds/recipes.test.mjs` uses
the actual source floor, obstruction and walk-edge functions for all mandatory
markers and infantry routes, schema topology, race gate/track markers and soccer
net access. Heavy verification still requires Blender export, Godot import,
host/guest visual walkthroughs, real vehicle route playback, bot navigation to
every mandatory objective and captures in the separate evidence directory.
