# Prepared native acceptance journey (unrun)

Run only with the parent's serial engine grant, integrated production dependencies
and the stock Godot 4.5.2 Compatibility renderer. Save evidence beneath the owned
presentation-evidence directory. Capture actual windows; source math is not a
substitute for fighter silhouettes, animation, FX, brightness or human feel.

1. Open Home, activate **Fighting** using Tab/Enter or the controller. Verify Home
   Replays, Settings and attract background behavior before/after returning.
2. On selection choose each of nine actual roster entries on both sides, cycle
   AI/local/training and all available initial stages. Check HP/archetype labels
   match roster.json. Helix must appear only with the pinned accepted dependency;
   Parallax stays absent. Select two different physical pad IDs and verify one
   pad cannot claim both players.
3. Start AI at each difficulty. Walk/jump/crouch and press all nine actions using
   actual keyboard/controller events; inspect current input and life/meter/timer.
   Test DeepSeek 36-tick back charge, Grok 18-tick down charge, Gemini resource/
   palm-band variant names, S3 simultaneous chord and Back+Grab. Held S3 must not
   create a normal throw or repeated edge. AI must win actual idle-player rounds
   and reach results through core commands; do not inject HP or match phase.
4. In local mode move into throw range by walking. P1 Grab; P2 Grab during the
   authored ten-frame tech window. Observe actual throw capture/tech event and
   paired animation, then repeat outside the window to show the real throw. Hold
   independent Guard (C/N or L3) against standing/crouching normals and test safe
   release. Record the cue's actual event vocabulary and timing before approving.
5. Pause with Esc/Start during action/hitstop. Visit Move list, Settings, rematch,
   selection. Rebind a key and check on-screen hints; reject reserved/duplicate
   keys. OS Alt-Tab/focus loss must clear held/queued input, pause authority and
   require release/new press after explicit resume. Physically unplug the owned
   pad while holding an attack/axis; no stale input survives, reconnect/reassign
   restores control only on fresh input.
6. Training: choose stand/crouch/high guard/low guard/tech/CPU dummies. Start an
   actual attack, pause and frame-advance one tick at a time. Compare visible core
   move frame to authored active-envelope boxes. Optional hurt/push/advantage
   fields must either show authoritative values or remain explicitly unavailable.
   Record inputs, replay from the captured core save, reset, compare combo/input
   history. 25/50% speed labels must be visible and affect only training. Learning
   routes remain proposed until core's 27-combo verifier approves them.
7. For each stage, two real fighters plus actual FX: capture neutral, both corners,
   maximum separation, maximum jump (including Grok/Gemini specials), throws,
   guard and super. Use normal inputs, or a **labelled training-only fixture** if
   the core owner supplies one; never claim fixture writes as versus proof.
   Inspect Basalt canyon/water/relay, Canopy branching trees/ravine, Crown receiver
   and Helix specimen/lightwell. Geometry stays behind the lane; no foreground
   leaves obscure fighters. Preserve recognizable materials, avoid bright white
   reflective backgrounds washing out silhouettes, and reject visible platform
   gaps/open-pit composition. Crop source paths/hashes are in source-proof.json.
8. Capture 1920×1080, 1280×800, and 760×520 at UI100/UI150. Inspect full health
   labels, timer, combos, input and modal scrolling/focus. Test low FX and reduced
   motion with the camera locked. Real GPU profile: frame median/p95, worst-case
   FX, visible surfaces/triangles, memory, GL Compatibility shadow behavior.
   Current stage shadows are disabled; do not enable expensive shadows without
   measuring the parent-agreed budget.
9. Let real AI/versus matches finish, rematch repeatedly, return Home. Verify all
   owned world/UI/FX/visual objects unload, authority does not run in menus, and no
   Node/FPS authority/award process starts. Check Home music/attract Settings and
   integrated Replays again. Parent owns package/export closure after acceptance.

Every item above remains **pending native execution**. The automated journey
prepares reproducible actual InputEvents but does not certify OS focus/controller
hardware, art composition, frame rate, competitive balance or throw choreography.
