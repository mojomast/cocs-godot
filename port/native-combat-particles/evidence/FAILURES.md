# Retained development failures and measurement caveats

These are development history, not passing result files.

1. First headless compile: `occupancy.gd:38 Cannot infer the type of "faces"`. Fixed by explicitly typing the concave shape's `PackedVector3Array`.
2. First shader compile: `Unknown identifier in expression: 'INDEX'` inside the spawn helper. Godot particle built-ins are stage-scoped. Fixed by passing the index and in/out state explicitly from `start()`/`process()`. The first CPU contract assertions passed despite the shader error, so subsequent rendered checks and the measurement runner explicitly reject `SCRIPT ERROR`, `SHADER ERROR`, and `ERROR:` log output.
3. `invalid-size-extreme-800.{png,json,log}` retains a real one-million-slot rendered run whose **actual PNG was 1280×800** despite the old harness's requested `800×600` JSON field. It is **not valid 800×600 evidence**. Fixed by assigning the Window size, disabling content scaling, supplying `--resolution`, recording actual viewport dimensions, and asserting both GPU screenshot dimensions and PNG header dimensions in the runner.
4. `failed-auto-display-xvfb.log.gz` (lossless full log) and `failed-auto-display-measurement-run.log` retain the first automated matrix launch failure. The shared `/tmp/.X11-unix` directory is root-owned mode 0755. No shared permission was changed. The runner now uses Linux abstract local X11 sockets with `-nolisten unix -nolisten tcp`, a private allocated display and a temporary directory honoring `TMPDIR` (fallback `/tmp/opencode`).
5. The driver warns that changing VSync mode is unsupported. This warning remains in rendered logs. All measured adapters report **Mesa llvmpipe software rendering**; hardware GPU performance is unknown. No smoothing, sample trimming, stall removal, or invented hardware FPS is used. Frame arrays include the screenshot readback/save hitch at frame 25; startup/shader compilation occurs before the 16 warm-up frames and is reported separately as configuration/wall time.
6. The first full matrix correctly failed its saturation assertion: static near-camera burst priority allowed those old bursts to expire while newer distant bursts repeatedly recycled other slots, so the end-of-run draw count fell below one million. `failed-saturation-*` retains that run. Burst priority now ages with its fading energy, while currently authoritative trails refresh their priority age. The stress fixture refreshes four bursts every six frames. This both improves long-lived pool fairness and keeps the final stress matrix saturated without bypassing the public event API.

`draw_slots` is actual submitted GPUParticles capacity, verified against the 2-million-plus scene primitive counter in Extreme; it is not a count of distinct visible pixels or a GPU particle readback. Bounds/solid/depth rejection and faded particles are deliberate. The retained invalid-size run still honestly shows that capacity, but is excluded from final two-resolution comparisons.
