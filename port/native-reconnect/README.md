# Native multiplayer reconnect

In the opt-in `--lobby-menu` route, a transport drop exposes **Retry / Reconnect** and **Leave**. Retry sends the source's room-token `join` only to the same WebSocket endpoint, room and expected map, within an 18-second in-memory window (the source's default disconnected grace is 20 seconds). The connection attempt times out after eight seconds. Leave, a protocol violation, or an explicit fresh connection destroys the ticket. No token is written to disk, command-line arguments, environment, UI, traces or diagnostic text. Career identity credentials remain a separate mechanism.

The source's `reconnected: true` welcome confirms reattachment. Its roster must echo the same actor and spectator assignment; host actions depend on the **current** roster hostId. A `reconnected: false` welcome means a fresh seat, including the source's read-only spectator assignment in a live round; the native client reports that honestly. Spectator input remains blocked after reconnect. The resumed `start` for the existing `roundRevision` clears stale snapshots/events/ACK and reseeds the camera from a new authoritative snapshot while preserving input sequence monotonicity. A genuinely new round resets input sequence. Pointer capture always requires a new click. The source limits a sudden sequence jump to `receivedSeq + 1`; thus a high native high-water after resume can cause source ACKs to climb from one before catching up, without resurrecting previous ACKs.

Career receives admitted `start` before the session's started signal and `results` before its results signal; `history` frames and nonfatal unsupported-history notices are forwarded to `Career.receive(client, frame)`. The career service owns result/history projection and duplicate-award handling. This lane does not settle progression locally.

An admitted welcome requires the matching queued create/join request; a cancelled or unsolicited welcome cannot mint a new room ticket or bind a career. An expired room-token join also carries the separately scoped career credentials, so the source can admit a fresh spectator without minting a new career identity. A resumed new round uses the source's new roster actor and resets native round caches/sequence; same-revision resumes require the previous actor. The source itself resets received/applied input counters on reattach; the native sequence remains monotonic to avoid reusing client-side sequence numbers, while source ACKs can restart at a low value. A non-lobby route falls back to its explicit launcher error state instead of showing a reconnect promise without a Retry widget.

## Verification

`node port/native-reconnect/journey.mjs` launches the real Node authority and a headless Godot client. Its controlled transport-close fixture verifies same actor/room/revision, monotonic input and new source ACK, current host roster, spectator reattachment/read-only behavior, endpoint/map/room binding, explicit leave clearing, and a shortened source-grace case where a fresh live spectator must **not** report reconnected. The shortened `graceMs:1000` is fixture-only; the native ticket remains 18 seconds. This is native protocol evidence, not a claim of two humans interacting with a graphical client. Existing spectator-context and session-recovery protocol suites also pass.

`node port/native-reconnect/offline-results.mjs` advances genuine source `Room.tick` fixed steps while the native transport is closed. The source time limit settles naturally; reconnect then verifies one authoritative results delivery on the same actor/room/revision. Its accelerated source clock is a controlled fixture, not a graphical human-play observation.

`godot --headless --path godot --script res://tests/protocol/reconnect_menu.gd` observes the native lobby controls at the disconnected and retrying phases: visible explicit Retry and Leave, bounded expiry disabled state, and no ticket in displayed text. The menu observer uses a synthetic session double; the socket journeys above use the actual authority.

Follow-up gate: `node port/native-reconnect/rendered-journey.mjs` runs the actual `world/session.tscn` and lobby UI under private Xvfb, with a real external protocol host. It clicks Retry/Leave through native pointer events after authority-terminated guest sockets, checks actor/revision/ACK/sequence, pointer release, chat cache, source profile continuity and host liveness, and captures the disconnected UI at 960×640, 150% scale. It writes a minimal summary and screenshot under `/tmp/opencode/native-reconnect-evidence-<pid>` (override with `COCS_RECONNECT_EVIDENCE`). This is a scripted graphical observer, not human acceptance. This follow-up gate and the revised socket journey must run when the serialized engine/server test slot is available.

Fixture correction retained: the first offline-results attempt advanced the source registry's bootstrap lobby rather than the actual live match, so the native observer timed out without a results frame. The fixture now selects the live `Room.match`, then advances its genuine fixed-step clock. No authority implementation or terminal frame was altered.
