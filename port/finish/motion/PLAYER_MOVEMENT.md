# Player movement: ordinary native session

## Source audit and selected seam

`game/core.mjs` already implements grounded acceleration/friction and sharp reversals, projected air steering, sprint/crouch slide and slide-hop, 0.10 s coyote time, 0.12 s jump buffer, variable-height jump release (`vy *= .45`), and reduced apex gravity. The Godot `world/combat_actions.gd` sends the ordinary recorded WASD, jump, sprint, crouch and mobility states through `world/session.gd`; `input_bindings/mapper.gd` translates remaps without injecting global events. No additional client-side jump buffers or speed/position prediction are appropriate: the authoritative source owns those rules. The extra verbs are accessible by holding sprint then crouch at speed for a slide, jumping from a slide for a hop, and pressing/holding mobility per the equipped harness.

The actual native gap was `world/session.gd`: it passed simulation velocity and source time to `world/local_motion.gd` only in campaign. Ordinary matches estimated eye velocity from packet **arrival** intervals. When multiple source ticks arrived together, a tiny receive interval could be clamped to 40 m/s and make the camera lurch even while ordinary movement remained responsive on the server. The existing helper has a 50 ms extrapolation ceiling, a 75 ms correction interval and a bounded authority correction speed; those remain unchanged.

## Implementation

- All ordinary session modes now pass finite authoritative actor velocity and finite source simulation time into the existing local rendered-eye smoother. Mounted actors use eye-position deltas across source ticks instead, because infantry velocity does not describe a moving seat. Bad/missing time and velocity retain the helper's receive-clock fallback; mode overrides such as Horde's own render-step policy are unchanged. Teleport, death, stale/focus and actor epoch paths still reset/reanchor camera state. Aim and inputs continue to use the authoritative camera direction, not a predicted actor.
- `first_person/inertia.gd` adds a restrained, source-velocity-driven lateral weapon lean (at most 0.009 m and 0.014 rad before the rig's hip/ADS blend). It settles analytically through the existing critically damped spring, follows actual braking/collision, and resets on visibility/actor lifecycle. The rig's existing takeoff/landing impulses and sprint lower remain; reduced motion zeros all these offsets.
- `first_person/session_binding.gd` adds a small, source-confirmed sprint optical cue (0–3 degrees), smooth at variable render `delta`. It is suppressed by reduced motion and fades as the existing ADS weight rises, reaching exactly the source ADS FOV at full aim. Round/eligibility loss restores base FOV. It does not alter look, spread, velocity, collision or shot direction. There is no new rig API.

## Verification and native acceptance

Source tests: `node --test game/movement-input.test.mjs game/arena-movement.test.mjs` — 13/13 pass. `git diff --check` passes. Added `godot/tests/world_motion/ordinary_modes.gd` for source-clock packet batching/rewind/reseed/death and bounded strafe/FOV/reduced-motion behavior; Godot was not run in this source-only lane, so this fixture and existing `godot/tests/world_motion/unit.gd`, `godot/tests/campaign/feel_motion.gd`, `godot/tests/first_person/binding.gd` remain native verification pending. No subjective movement-feel or native FPS claim is inferred from source tests.

Native acceptance should launch an ordinary map (not campaign), capture pointer with a real click, record normal-rate W press/release and strafe/reversal, sprint→crouch→slide→jump, one short jump tap and one held jump, airborne steering, ADS while sprint drops, reduced-motion toggle, then release pointer/focus and respawn. Correlate snapshots' source `time`, actor `vx/vy/vz` and position with camera motion and ordinary input ACK/neutral releases; inspect a clip for batched-snapshot surges, landing settling and sight/reticle alignment. Repeat on a traversal path and in Horde to confirm its own render override. Server physics values are unchanged.

Refs: [Gaffer, Fix Your Timestep!](https://gafferongames.com/post/fix_your_timestep/) for simulation/render cadence separation; [Xbox Accessibility Guideline 117](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/117) for minimizing/switching off unnecessary motion. These are implementation principles, not external acceptance evidence.
