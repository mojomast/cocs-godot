# Candidate design v1

Backend: native flat-normal ArrayMesh; original convex octagonal sections with a small rolled/chamfered rim, tapered lower/upper cross sections and closed caps. Meters, Y-up, -Z-forward, actor origin at source Y+0.9. Direct named children preserve existing attachment tests. No colliders, skinning, executable recipes, gameplay updates or external textures.

Claude/Warden: upright ceramic brow, broad shield chest narrowing to waist, symmetrical shoulders and segmented boots. Grok/Outrider: narrower wedge helmet, asymmetric shoulder armor, offset chest plates and compact pack. Meta/Bulwark: flatter wider turret helmet, broad square torso, substantial shoulders, twin back cylinders approximated by the same octagonal prism operation. All remain within 0.7m body width and 1.8m standing height; crown top +0.9, sole bottom -0.9. Base shell must be readable from side/back, not only front details. Six other IDs and unknown IDs use Warden geometry with original per-character/fallback color.

Recipe schema: version=1, generator=faceted-operator-1, seed=0, variants exactly claude/grok/meta. Each contains at most 64 uniquely named parts; operation only prism; position/size are finite bounded triples; yaw is finite within [-PI,PI] for the static elbow-to-palm support chain; lower/upper width factors 0.35..1; bevel 0.01..0.25; material one of dark/trim/armor/identity. No paths/expressions. Validate exact keys, no bool-as-number. Cache meshes by canonical serialized part shape, with approved recipe limits preventing arbitrary growth. Identity switches swap precomputed mesh references and position only; all variants share semantic names. Helmet and Muzzle instances remain stable. No per-frame builder.

Material budget 4/actor, textures 0. Proposed cap 64 meshes/surfaces and 65 nodes, <=5000 triangles and <=15000 flat-normal vertices. This consciously increases baseline 312-triangle silhouettes but avoids source web renderer's higher-detail tiers. Warm population construction provisional cap 10x baseline medians; report actual timings and do not equate CPU construction with GPU cost. Render 1/16/32 actors identically for baseline/candidate; report frame-time distributions and real renderer counters before any performance acceptance.

Meaningful sockets: existing generic Weapon/WeaponGrip/Muzzle at unchanged reference positions. Hands meet the grip and fore-end; no reserved pulse-rifle art. Arms are static readiness/grip pose, NOT animated aiming acceptance. Team markings remain separate one/two stripe instances. Variant identity changes cannot change team assignment or another actor's materials.

Outputs: recipes.json, recipe builder, candidate.gd, preview.gd/tscn; tests/player_models numerical checks; native-player-models verify.py, staged preload patch, retained logs/renders/metrics and HANDOFF. Acceptance: strict schema negative tests; finite/index/triangle/winding/bounds checks; all IDs/team forms/material isolation/stability; two clean canonical rebuilds; inherited gates against privately patched candidate; matched neutral and map-lit fixed-camera views at both resolutions; population rendering; unchanged normal-rate server integration; editor-free Linux export. At most three documented visual repair iterations per candidate. Unfinished acceptance remains explicitly pending, never inferred from import alone.
