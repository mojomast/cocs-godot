## Geometry and positive acceptance

The new positive fixture uses the original fixture's `rotated()` operation, not
an alternative solver model. Every target vertex and goal Y derives from the
fixed rise; native geometry telemetry records actual shape data, body/shape RIDs,
body/shape transforms and velocities. The validator independently reconstructs
the canonical six world-space vertices and binds the actual collision mesh to
them. A receipt-declared arbitrary rise, .15 plane on a .18 case, or substituted
radius cannot pass the ordered census and shape checks.

Candidate configuration already accepts the actual target face plane, so no
candidate application code needs modification. The live original planner may
reject .18, or the unchanged parity proof/guard may fail. Such a failure stops
the campaign honestly: no fallback height, relaxed forward-motion condition,
mixed-support acceptance, epsilon widening, rollback or corrective rerun exists.

Whole positive admission requires **all four pairs** to pass:

* Baseline:120 consecutive stalled continued-input responses before goal,
  grounded and with a recorded intended-target ordinary slide contact on every
  counted response. The contact has numeric shape index0, finite unit normal,
  point in the unchanged low band below.25 and on the actual target plane, and
  opposing horizontal intent dot≥.98. This uses the recorded ordinary collision,
  not AL's archived result or a stale proposal witness. It does not import AL's
  separate per-frame downward-base-query protocol into the paired campaign.
* Candidate: at least one applied and verified lift, every applied lift verified,
  no terminal candidate fault, unchanged cumulative limits, at least three
  consecutive ordinary grounded continued-input full-footprint landing responses,
  and arrival along≥1 with fresh exclusive target support on the actual rise.
* Applied-response support retains live actual transform/body RID, numeric
  collider/local shape identities, empty exclusions, max32 unsaturated contacts,
  downward margin+.0001 motion and original recovery/separation flags, finite
  ordered fractions, static support and explicit46° floor checks. Missing or
  mixed support cannot qualify. Final arrival repeats the reviewed fresh support
  query at the actual body transform and actual target face plane.

The support, guarded-response and forward/endpoint evidence functions otherwise
retain their exact reviewed operands. World-small1µm budgets and the planner's
strict rise<.2499 limit remain unchanged. Whole-frame displacement, parent-only
position delta, parent real velocity and last motion stay distinct evidence;
this fixture change does not resolve production pre-lift motion accounting.

The original native finish/counter semantics are retained: completed includes
recorded failed profiles/pairs, interruption is distinct, later cases remain
unrun, and absent/fatal paths may have unknown internal work. Native driver checks,
native predecessor validation and host whole-receipt replay are separate layers;
native finish is not a newly added in-memory whole-policy validation call. A
successful supervisor receipt additionally requires full new-phase Python replay.
Existing outcome strings such as `synthetic_group_pass` are retained inside the
**distinct calibrated phase**, not applied to old receipts.

## Source/grant/predecessor sealing

`prepare.py` requires read-only AL and AK roots, verifies **AL33 and AK51** exact
inventories, and writes one fresh lowercase `calibrated-admission-*` namespace
only on an explicit future preparation call. No such call was made here. The
common source seal includes17-script closure, host inputs, all15 production
dependencies, preserved-source pins, fixed positive cases and selection digest.
It never creates a grant or starts a process.

The future grant must have exactly `phase`, `mode`, `allowedGroups`, `grantId`,
`authorized`, `expiresUnix`, `sourceSha256`, `engineSha256`. Only ordered unique
subsets of the three known groups are accepted; allowing a later group does not
remove its prerequisites. Godot4.5.2 must be an absolute nonsymlink path with the
unchanged binary hash `5803746bbe055bee0f07a3c5b0dd347719bd45599f3d34519a8a0beaf83014ae`.
There is no filled grant/template, grant writer, all-groups runner, queued work,
custom-height CLI, force flag or implicit map scope.

Before each separate invocation, under the shared lock, the supervisor rechecks
source/grant/binary and frozen lineage, then validates **every earlier group**:
new phase/mode/group, common hashes, complete canonical native census and operands,
exit0/failed=false, no script/admission error, exact native/supervisor hash binding,
and three strictly ordered measured empty-group audits between lock acquisition
and release-pending timestamps. Raw predecessor logs are also checked. Native
predecessor policy repeats native/supervisor validation on those hash-bound files.
Owner inspection and a passing checkpoint after each release are still required
before authorizing the next group; no source path automatically invokes it.

The new native source-census gate compares individual numeric operands through
`spec_equal`, not numeric array membership/equality assumptions after JSON parsing.
Finite integer guards and explicit0/1 comparisons remain in both validators.

New Python modules use relative imports inside a checkout-specific private package
loaded by `cli.py`; they never install themselves as global `policy`, `evidence`
or `prepare`. The few frozen AG file/ownership utility imports restore temporary
legacy names. Tests exercise old and new versions without silently shadowing old
validators. The old phase's Policy is never called on a new-phase receipt or
made to accept one through header rewriting.

Supervisor lifecycle tests mock every child/process/signal operation. A clean
release cannot override a failed workload. Polling and post-exit scans catch
`ADMISSION_FAILURE`, script and parse errors even after exit0. Group consumption
is written before Popen; launch failure cannot retry that group. Unknown audits,
PID reuse, permissions, ESRCH, handler restoration and receipt-write failures
retain fail-closed behavior. Raw output caps are64MiB result/4MiB log; logs are
retained without normalization. Internal physical-call totals are never inferred.
